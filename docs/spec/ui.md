# 管理 UI

利用者向け `/watch` の画面と認証は [site.md](site.md) に記載する。この文書は管理コンソールの仕様。

`ui/` の React アプリケーション。Go サーバーに組み込まず、Vite または別の静的配信環境で提供する。起動手順・環境変数・テストコマンドは [ui/README.md](../../ui/README.md)。バックエンド API の形式は変更しない。

## 画面

| 画面 | 内容・操作 |
|:--|:--|
| チャンネル | 配信・リレー・ローカル視聴数、チャンネル一覧、配信開始、停止、再接続 / YP 再通知 |
| チャンネル詳細 | メタデータ、トラック、空き枠、接続一覧・リレー切断、IPv6 対応ツリー、配信情報編集 |
| ストリームキー | 発行、表示・コピー、失効。キーは既定で伏せ字、生成は crypto.getRandomValues の 16 bytes |
| ノード情報 | エージェント、PeerCast / RTMP ポート、YP 一覧と配信チャンネル数 |

## 通信と操作

一覧・詳細・ノード情報は 30 秒周期と手動操作で更新する。読込中・最終更新時刻・エラーを表示し、取得失敗を空の正常結果として表示しない。再取得失敗時は前回のデータを残し、対応する停止・切断操作は無効にする。

`useResource` は各取得を AbortController と effect の有効フラグで管理する。再取得・アンマウント時は要求を中断し、古い結果を採用しない。選択詳細は channelId を React key として作り直し、表示している接続と操作対象のチャンネルを一致させる。

配信ダイアログはキー取得済みかつ有効なキー選択後に送信できる。取得失敗なら再読込ボタン、未発行ならキー画面への案内を表示する。ビットレートは空欄が自動、指定時は 1–2147483647 の整数。

情報編集時は `getChannelInfo` で保存直前の track を取得し、`setChannelInfo` の第 3 引数へ渡す。読み取りが失敗した場合は更新しない。外部更新との原子的な競合制御はない。

更新操作は同期ロックと disabled 表示で二重送信を防ぐ。ダイアログは処理中に閉じられない。停止・切断・失効は確認を挟み、成功・失敗を表示する。リレーの再接続は要求の受理までであり成立を待たない。配信の YP 再通知は全配信を対象とし、YP 未設定なら no-op。

RPC は HTTP ステータス、JSON-RPC 2.0、応答 ID、result/error の有無を確認し、15 秒でタイムアウトする。更新操作は自動再送せず、タイムアウト時は反映状況の確認を促す。

## 表示・アクセシビリティ

日本語ラベル、ラベルと関連付いたフォーム、ネイティブ button によるチャンネル選択、フォーカス表示、メインコンテンツへのスキップリンクを提供する。ダイアログは名前を持つネイティブ dialog で、非送信中は Escape で閉じる。

ライト / ダークは OS の設定に従う。700px 以下ではフォームを 1 列にし、表は名前付き・キーボード操作可能なスクロール領域に収める。状態は色だけでなく文字で表す。ストリームキーと配信ソース URL は伏せ字を初期表示とし、表示切替とコピーに対応する。

## サイト管理者用のログ画面

X管理者としてサイトの管理パネルを開いた場合、ナビゲーションに「ログ」を表示する。操作ログ・配信履歴の検索、詳細とRTMP受信区間、関連ログの参照を行う。[詳細仕様](audit.md#管理パネルでの閲覧)。管理パネルとログ画面のコードはその入口を開いた時に読み込み、サイト閲覧の初回読み込みから分離する。
