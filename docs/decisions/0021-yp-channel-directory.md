# 0021: YP 番組カタログを管理 API と視聴サイトで共有する

追記: 独自の再生ボタン・YP 診断の画面表示は後続依頼の [ADR 0022](0022-viewing-pages-and-comments.md) で変更した。カタログ・中継の制限は維持する。

- 状態: 採用
- 日付: 2026-09-14

## 背景

ユーザーは peca-live が使用する `updateYPChannels` 相当の実装を依頼した。自ノードだけの一覧では番組を発見できない。参照した YP 資料では、PCP の掲載接続とは別に HTTP の `index.txt` を取得する。

## 決定

- `[[yp]].channels_url` を明示する。PCP `addr` から HTTP のホスト・パスは推測しない。全エントリの一覧を取得し、配信掲載先を選ぶ `-yp` とは分離する。
- `internal/catalog` を追加し、管理 JSON-RPC とサイトが同じ 60 秒キャッシュ・同時取得の集約を使う。失敗もキャッシュし、失敗した YP は最後の成功から 5 分未満だけ古い一覧を保持する。部分障害で他 YP の番組まで消さないため。サイトでは失敗・古い一覧・未設定を明示する。
- ADR 0009 の個別例外として `updateYPChannels` の名前と peca-live が消費する PCS の返却フィールドを採用する。管理 API 全体の互換性は保証しない。PCS の 18 秒ではなく peca-live の取得周期に合わせた 60 秒とする。
- ADR 0019 の「自ノードだけ」を拡張する。サイトはカタログと自ノードを ID で統合し、ゼロ ID の告知行を除外する。再生要求時にだけ既存 Manager で中継を開始する。カタログの接続先をブラウザーに渡さず、任意の tip・URL・管理操作は受け取らない。
- サイトによる新規接続はカタログ内の public IP リテラルの tracker のみ。名前解決による内部ネットワークへの接続を避けるため hostname・private/loopback/link-local は不可。既存の公開 PCP の接続先選択・中継は変更しない。
- 新規中継の前に視聴枠を確保する。サイト経由の新規中継はノード内の中継数が `site.max_relay_channels`（既定 8）未満の場合のみ。視聴を閉じるたびに共有中継を止めず、既存の Manager の無利用タイムアウトで回収する。ノード共通の `max_relay_channels` も引き続き有効。

## 却下した案

- ブラウザーから YP / tracker URL を受け取る: サイト権限で任意のサーバーへ接続できてしまう。
- ログインや一覧表示で全番組を中継する: 視聴前に帯域・接続枠を消費する。
- YP 取得失敗を常に空の正常応答だけで表す: 番組不在と設定・通信エラーを区別できない。
- PCP 登録 URL のホストに `/index.txt` を付ける: 0yp の `/yp/index.txt`、SP の `/sp/index.txt` のようにパスも異なる。
