# 配信フォームの履歴保存と掲示板参照

## 状態

採用

## 日付

2026-09-15

## 背景

pcgw に寄せたチャンネル作成フォームで、前回の設定を初期表示し、過去の設定を選んで読み込みたい。履歴は同じ X アカウントで端末を変えても再利用できる必要がある。現状は単一 Go プロセスで配信枠とキーを管理し、履歴に必要なのは各ユーザーの直近10件の小さな設定だけ。

## 決定

- チャンネル作成成功時の5項目と日時を、サイト専用のディレクトリにユーザー別 JSON として最大10件保存する。未送信の編集は保存しない。
- 所有者は認証済みセッションから決める。キー再発行から独立させ、ファイル名はアカウント識別子の SHA-256 とする。ハッシュ化は暗号化ではなく安全な固定長ファイル名のため。
- 形式バージョン1。サイト操作のロック内で読み書きし、一時ファイルの同期・rename で置換する。保存失敗時は作成した枠を停止し、作成要求を失敗として返す。履歴破損時は上書きしない。
- 複数プロセスで同じディレクトリを共有する運用は対象外。

却下した案:

- MySQL: 今回の用途には別サーバー・接続設定・認証・バックアップ運用の追加が大きい。複数ノードで履歴を共有する場合に再検討する。
- SQLite: 別サーバーは不要だが、この範囲では SQL スキーマ・ドライバー・マイグレーションを追加する利点が少ない。横断検索や多数の関連データが必要になったら再検討する。
- ブラウザーの localStorage: 別端末で共有できず、サーバー再起動を越えたアカウント単位の履歴にならないため採用しない。
- ストリームキーファイルへの追記: キー管理とサイトのフォーム履歴は責務が異なるため分離する。

## 結果・影響

掲示板参照は、チャンネル作成前のフォームに必要なため、認証済み本人からコンタクトURLを受け取る専用 API を追加する。ADR 0022 のチャンネル由来URL限定はコメント閲覧 API に維持し、フォーム参照に限って例外とする。任意ホストの取得は採用せず、既知のしたらば / jpnkn のURLから内部で取得先を組み立て、既存の公開IP制限・リダイレクト拒否・サイズ制限を再利用する。新スレ移動は可逆な入力変更なので確認ダイアログを設けない。

DB の導入は不要。`site.broadcast_history_dir` を永続領域として保全・バックアップする。省略時は設定ファイルと同じディレクトリ配下に置き、Docker の既存 `/config` マウントでも永続化する。履歴は今回の導入後に成功したチャンネル作成から蓄積する。ジャンルは公開用 `yp` 補完前の入力を保存する。
