# 0020: loopback 限定の開発用ログインを設ける

- 状態: 採用
- 日付: 2026-09-14

## 背景

X のアプリ登録・HTTPS callback の準備前に、ローカルで視聴・配信を確認したいとユーザーから依頼された。実際のサイト API を利用するため、画面だけのモックとは分ける。

## 決定

- `site.dev_login` を明示的に有効にした場合だけ、X の資格情報を要求せず開発用セッションを作成できる。既定 false。資格情報の欠如から自動的に認証を省略しない。
- 起動条件は HTTP の loopback origin と、IP リテラルの loopback 待受。公開 / HTTPS origin、全インターフェースや LAN への bind は拒否する。
- 開発モードの全サイト要求は実接続元の loopback と Host の origin 一致を検査する。転送ヘッダーを接続元判定に使わない。ログインは POST のみで、設定と一致する Origin が必要。
- X の経路の代わりに `POST /site/api/dev-login` を登録し、固定の `dev-local` ユーザーで通常セッションを作る。所有者の保存名は `site:dev:local` として X ID の名前空間から分離する。
- セッション・CSRF・本人の操作・視聴制限・内部 HTTP メディア認証は省略しない。通常モードでは開発用 endpoint を登録しない。起動ログと画面で開発モードを明示する。

## 却下した案

- **全 API の認証を除去**: 本番への混入と、セッション / 権限制御を検証できない問題がある。
- **X の秘密情報が空なら自動で開発モード**: 設定漏れを認証省略として扱ってしまう。
- **localStorage の擬似ユーザーだけで UI を切替**: 実際の Go API・配信・視聴の確認にならない。

## 結果・影響

X の認証往復は検証できないが、実ノードを用いた視聴・配信操作を確認できる。開発ユーザーは全ブラウザーで共有され、通常ユーザーと同様にキーが保存される。開発時の配信も公開 PCP へ流れ得る。

このガードは任意の信頼済みプロキシによる誤公開まで防ぐ保証ではない。開発モード中は Vite と Go サイトを HTTPS トンネルや外部プロキシで公開しない。公開する際は `dev_login = false` にし、X の設定を行って再起動する。
