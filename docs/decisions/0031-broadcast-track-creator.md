# サイト配信のトラック作成者に接続元IPを設定する

## 状態

採用

## 日付

2026-09-15

## 背景

ユーザーが pcgw の `IP via Peercast Gateway` と同じ処理を、`IP via PecaMI` の文字列で追加するよう指定した。pcgw はチャンネル作成のHTTP要求のIPをtrack.creatorに設定する。本番のmiはCaddy経由なので、ソケットの接続元だけではプロキシのIPになる。

## 決定

サイトのチャンネル作成時に `TrackInfo.Creator` を `接続元IP via PecaMI` として設定する。PCPでは `trck` 内の `crea` に入り、YPと下流へ公開される。フォーム履歴にはIPを保存せず、作成のたびに算出する。

`site.trusted_proxies` のCIDRに含まれるソケット接続元だけ、X-Forwarded-Forを右から左に辿って元IPを解決する。最初の非信頼IPで止まり、不正なホップを読み飛ばさない。未設定は転送ヘッダーを無視する。IPv4-mapped IPv6はIPv4に正規化する。認証や開発ログインの接続元制限にはこの判定を流用しない。

却下した案:

- X-Forwarded-For先頭を無条件に採用: 外部から偽装できるため。
- RTMPの接続元を利用: pcgwの作成要求IPと異なり、OBS接続まで値が決まらないため。
- 固定のIPや古い履歴のIPを利用: 今回の作成元を示せないため。

## 結果・影響

新しく作成するサイト配信に適用する。既存配信の遡及更新・管理APIの挙動変更はしない。プロキシ環境では転送ヘッダーを正しく設定するプロキシのCIDRを明示し、信頼範囲から第三者が直接要求を送れないよう配置する。ヘッダー欠落・不正時は判別できた接続元までを使う。
