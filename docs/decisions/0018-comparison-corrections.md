# 比較で判明した通知・状態・再接続の差異を修正する

## 状態

採用

## 日付

2026-09-14

## 背景

[3 実装比較](../reviews/2026-09-14-implementation-comparison.md) で、既存の「互換」という記述では説明できない D01–D14 を確認した。ユーザーから、理由のない差異を修正する依頼を受けた。以下は当初の意図を推測した遡及記録ではなく、今回の修正判断である。

## 決定

- BCST はローカル配送と転送を分け、group/dest/TTL に従って上下流へ運ぶ。子孫 HOST が tracker に届く経路を復元し、上流 writer は直列化する。
- HOST/API の枠判定を共通化し、全体制限を反映する。oleh の IP・ポート状態は family ごとに共有する。GIV 非対応でも閉鎖・未確認のポートを開放済みと広告しない。
- Receiving は data の最終受信から 30 秒以内、切断時は即 false とする。厳密な瞬間受信レートの模倣は採らず、短い入力間隔の揺れでフラグを振動させない。過去のバッファだけで true を維持する案は却下する。
- 古い初期バックログの年齢を送出遅延として扱わず、出力へ接続した時点から計測する。PCP の data 停止だけによる 5 秒切断は除去する。最古からの開始・uint32 の位置空間・パケット数ベースのバッファは ADR 0002/0015 の既存契約として維持する。PCS の最新開始可能点への変更は今回行わない。
- 上流 handshake は 18 秒で打ち切る。HOST/統計は 180 秒で失効させ、切断した直下から届いた子孫報告も除去する。退出候補は非 local の firewalled、または満杯かつ下流 0 に広げる。
- リレーの `bumpChannel` は対象ソースの再接続要求とする。配信ソースは外部 RTMP push なので接続を破棄してエンコーダーの再接続に賭ける案は採らず、従来の YP 再通知を維持する。RPC 成功は再接続成功の保証ではない。
- BroadcastID を config と同じディレクトリの `broadcast_id` に保存する。32 桁 hex + 改行、0600。作成は完全な一時ファイルの link により既存ファイルを上書きせず公開し、競合時は先行作成者の ID を読む。不正ファイルを自動再生成すると配信 URL が変わるため、起動エラーにする。
- YP の既定周期は PCS と同じ 30 秒に変更し、root.uint の更新を継続反映する。変更・停止は 1 秒周期で検出する。全 Channel の setter に YP 固有の通知依存を追加する案は避け、比較可能なスナップショットで管理する。
- IPv6 の IP アトム・PCP version 100・接続先表現に対応する。依存ライブラリの IPv4 専用 rip 処理は pcputil で補完する。
- 同一 NAT の判定は外部 IPv4 の一致を維持する (D12 の部分的な差異)。同じ NAT 内の複数ノードは異なる公開ポートを割り当てられるため、PCS の IP+port 一致へ変えると LAN 接続が選べなくなる。GIV を要求する候補、unspecified/loopback の広告を除く方針も維持する。これは今回の技術的理由に基づく判断であり、以前から理由が記録されていたという意味ではない。
- 音声のみ FLV は video bit を広告せず、完全な AudioFrame を送出開始点にできる。映像ありのキーフレーム待ち、Fragment 除外は維持する。
- ツリー API は新鮮な HOST の endpoint 関係を使う。推測した Receiving=true や固定人数はやめ、報告のない値は未知としてゼロ/false を返す。循環する報告で再帰を継続しない。

## 結果・影響

BroadcastID 導入後は再起動しても配信 URL が安定する。導入前のプロセス内ランダム ID は復元できないため初回移行では ID が変わる。`broadcast_id` と `stream_keys.json` を一緒に保管し、通常運用で削除しない。config ディレクトリに初回作成の書き込み権限が必要。別実装の ChannelID との一致は保証しない。

BCST・広告・再接続の欠落を修正するが、PCS/yt のすべての実装詳細をコピーするものではない。実機相互接続、全コーデック、IPv6 の多段構成は別途検証が必要。
