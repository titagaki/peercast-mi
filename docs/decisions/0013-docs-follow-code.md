# 0013: 仕様書と実装が食い違ったら仕様書を実装に合わせる

- 状態: 採用
- 日付: 2026-09-13

## 背景

2026-09 のレビューで、`spec.md` / `spec-components.md` に「指数バックオフで再接続」「pcp\n magic を送る」「bcst ttl=7」「HTTP はデータを待ってから 200 を返す」など、その後 PeerCastStation 互換のために意図的に変えた動作が古いまま残っていた。実装側の変更は `peercaststation-compat.md` に根拠付きで記録されていたため、実装が正であることは明らかだった。

## 決定

- 仕様書 (`docs/spec/`) は「現在の実装がどう動くか」を書く。実装と食い違ったら、実装に判断の記録 (decisions / compat ノート) があるかを確認し、あれば仕様書を実装に合わせる
- 実装側に記録がなく、仕様書の方が意図を表している場合だけ実装を直す。その判断も decisions に残す
- 動作を変えるコミットでは `docs/spec/` の該当箇所を同時に更新する。判断の背景は `docs/decisions/` に書き、仕様書には書かない
- 未着手・保留の作業は [docs/tasks.md](../tasks.md) に書く。仕様書や CLAUDE.md に「未解決事項」を散らさない

## 結果・影響

- 仕様書が「あるべき姿」ではなく「現状の記述」になる。設計意図は decisions 側で追う
- ドキュメントの分類: `spec/` = 現在の動作、`decisions/` = なぜそうしたか、`reference/` = 外部プロトコル等の参照資料、`tasks.md` = これからやること
