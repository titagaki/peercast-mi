# 0023: サイトの公開パスを明示設定する

- 状態: 採用
- 日付: 2026-09-14

## 背景

ユーザーがサイトを `https://yayaue.me/mi/` に配置し、既存の Caddy・0yp と同じインフラリポジトリで運用する方針を指定した。従来のサイトはルート配置が前提だった。

## 決定

- `site.base_path` を追加し、空文字なら従来どおりルート、`/mi` なら全サイトルートに同じ接頭辞を付ける。Origin の意味は変更せず、CSRF 比較にパスを混ぜない。
- UI の Vite base は `PEERCAST_SITE_BASE_PATH` で一致させる。Docker では UI を同じビルドに含めて、アセットとブラウザー側の URL をそろえる。
- プロキシはパスを保持する。OAuth callback・復帰先・cookie Path もアプリが構築する。転送ヘッダーから公開パスを推定しない。
- 既存のルート配置を維持し、JSON-RPC のパス・認証と公開 PCP の挙動は変更しない。

## 却下した案

- Caddy だけで接頭辞を削る: HTML だけでなく API、画面リンク、認証の戻り先がルートに向いてしまう。
- Origin に `/mi` を含める: ブラウザーの Origin ヘッダーと一致しなくなる。
- `/mi` をコードに固定する: ローカル開発・既存のルート配置を崩す。
