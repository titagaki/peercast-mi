# 0022: 一覧・視聴・配信・管理のページ分離と掲示板閲覧

- 状態: 採用
- 日付: 2026-09-14

## 背景

ユーザーが `/` の一覧からチャンネル名リンクで個別視聴へ移動し、自動再生と peca-live 相当の掲示板コメントを表示することを指定した。また視聴画面の技術的な状態表示・独自再生ボタンをなくし、管理画面を別パスへ移動して配信開始・キー発行を取り除くよう依頼した。

## 決定

- `/` は一覧、`/channels/<id>` は視聴、`/broadcast` は本人の配信、`/admin` は管理 UI とする。通常のリンク遷移を使い、直接 URL・再読み込みでも同じページを表示する。旧 `/watch` は Go では `/` にリダイレクトし、Vite の UI では一覧として扱う。
- ADR 0021 の明示的な再生ボタンを、個別ページを開く操作に置き換える。一覧表示では映像を取得しない。個別ページでは音声付き自動再生を試み、ブラウザーが禁止した場合のみミュートで再試行する。再生・停止・音量・全画面などはブラウザー標準のプレイヤー controls にまとめる。
- 認証は維持する。X ログイン後は検証済みのサイト内 `next` へ戻す。外部 URL や管理パスを復帰先として受け付けない。
- YP 別の取得成功・未設定等は閲覧画面に出さず、診断用 API の情報は維持する。管理 JSON-RPC はサイトから汎用転送しない。管理 UI の機能を減らすだけで既存 RPC メソッドは削除しない。パスの変更だけを認証対策とはしない。
- `internal/site` で掲示板を取得・テキスト化する。したらば / JPNKN のスレッド選択、最新 30 レス、新しい順、10 秒更新を採用する。投稿や掲示板サイト全体の埋め込みは行わない。
- 接続先はチャンネルの連絡先から導出し、利用者から URL は受け取らない。したらばと `bbs.jpnkn.com` にホストを限定する。元の peca-live の広い URL 正規表現は採用せず、DNS 結果の検査・IP 固定接続・リダイレクト禁止・取得上限でサーバーからの任意接続を防ぐ。既存 ADR 0019・0021 のサイト権限分離を維持するため。
- EUC-JP / Shift_JIS は `golang.org/x/text/encoding/japanese` を使い、手書きの変換表や Ruby / NKF 実行を導入しない。

## 却下した案

- 自動再生のためブラウザー設定の変更を要求する: 一般の閲覧者に強制できない。ミュートへの切替と標準 controls で対応する。
- 掲示板 HTML を iframe / innerHTML で表示する: 外部スクリプト・追跡・表示崩れを持ち込むため、取得したテキストだけを表示する。
- 任意の掲示板 URL をブラウザーから指定する: サイトサーバーを踏み台にする危険がある。
- 管理 RPC 自体からキー発行・配信開始を削除する: ユーザーが指定した範囲は管理パネルであり、既存ツールやノード API を壊す必要はない。
