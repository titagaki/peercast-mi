# 0033: X管理者に監査ログの検索・配信履歴画面を提供する

- 状態: 採用
- 日付: 2026-09-17

## 背景

ユーザーから、MariaDBに保存したログを管理パネルで確認したいと依頼された。ADR 0032の初期段階ではSQL参照と記録状態APIのみを提供していた。

## 決定

- X管理者用の管理パネルに「ログ」を追加し、操作ログ・配信履歴・RTMP受信区間を閲覧できるようにする。一般利用者・開発ログインには公開しない。直接ノードAPIのBasic認証は履歴閲覧の権限として使わない。
- サイト専用のGET APIで固定列を取得し、検索値はSQLのパラメーターにする。既存の監査テーブルと索引を利用し、DDLは変更しない。
- 日時・IDの降順でカーソルページ送りする。1ページ50件、API上限100件。件数全体のCOUNTや大きなOFFSETを必要としない。
- 既存のactor/ownerの区別を保持し、配信枠作成・メディア開始・実終了・中断検知を別の時刻として表示する。終了不明を現在時刻や最終受信時刻で補わない。
- 閲覧用DBプールを記録writerと分け、同時検索は2件、1要求3秒まで。認証・入力検証の後にSQLを実行する。IP検索は期間指定・31日以内に制限する。
- APIは既存のno-store方針を継続し、SQLエラー本文や資格情報を応答しない。payloadはGoの許可済み型へ読み戻し、DB内の未知JSONキーをそのまま返さない。
- UIは過去7日を初期範囲にし、条件クリアで古い履歴も取得できる。日時は端末のタイムゾーンを明示して表示する。記録の無期限保存は維持する。
- 管理画面とログ画面を必要時に読み込む。視聴サイトの初回読み込みへ履歴UIを追加しない。

## 却下した案

- 汎用SQL実行・全テーブルブラウザー: 必要なのは操作・配信の確認であり、任意SQLや秘密列の公開は不要。
- 全履歴をブラウザーへ取得して検索: 無期限保存ではデータ量が増え続ける。
- writerと同じ2接続を検索に使う: 検索待ちで記録の取り込みを占有する。
- 直接JSON-RPCへ履歴を追加: X管理者専用の既存サイト入口で認証と公開範囲を明示する。
