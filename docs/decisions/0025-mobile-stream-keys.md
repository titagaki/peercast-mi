# 0025: サイト発行キーを小文字英字2文字＋数字4桁にする

- 状態: 採用
- 日付: 2026-09-14

## 背景

スマホで配信するため短いストリームキーが必要との依頼。ユーザーの最終指定は小文字英字2文字＋数字4桁。

## 決定

- サイトの発行・再発行は `ab1234` 形式。暗号学的乱数で676万通りから一様に選び、既存キーとの衝突と再発行時の旧キー再選択を避ける。
- 既存キー、保存形式、管理APIの任意キー指定、OAuthセッション用の長い乱数は維持する。配信枠がある間の再発行拒否も維持する。
- 短いキーの推測試行を抑えるため、RTMP Publish をIPごと毎60秒10回・ノード全体120回に制限する。再接続で回避できないよう接続間で共有する。送信中メディアは制限しない。
- これはサイトの入力容易性とノード独自認証の判断であり、PeerCastStationとの互換性を目的としない。

## トレードオフ

従来の32 bytes乱数より推測耐性は低い。試行制限は推測を不可能にはせず、同じIPやノードへの試行が集中すると正規の再接続も最大60秒待つ。公開RTMPを用いる既存のユーザー指定を維持するため、入力接続自体は暗号化されない。

## 却下した案

- 数字6桁: ユーザーが英字2文字＋数字4桁へ変更した。
- 長いキーだけを継続: スマホでの手入力を短くする依頼を満たさない。
- 既存キーを自動交換: 設定済みのエンコーダーが接続できなくなる。
