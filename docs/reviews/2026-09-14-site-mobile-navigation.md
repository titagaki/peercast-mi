# サイトのスマホ向けナビゲーションとライブ表示

2026-09-14。既存の未コミット変更に追加した UI 改修。Go・認証・中継処理はこの改修では変更していない。

後続の [白基調・チャンネル情報の調整](2026-09-14-site-white-channel-info.md) でサイトの配色と文字情報・アイコンを更新した。下記はこの改修時点の検証記録。

## 変更と理由

| 対象 | 変更 | 理由 |
| --- | --- | --- |
| ナビゲーション | 右上のメニューに一覧・配信・ログアウトと利用者名を集約 | ユーザー要望。スマホでヘッダー下に操作行が積み重ならないようにする |
| 管理パネル | フッターに小さな `/admin` リンク。操作領域は高さ 44px | ユーザー要望。目立ちすぎず、タップしやすくする |
| スマホ | ヘッダー・余白を縮小、フォーム文字 16px、動画と掲示板を縦配置 | 視聴内容への到達を早め、狭い画面での操作を改善 |
| 動画 | Chromium / WebKit の標準シークバー・時間表示を隠し、ライブ配信ラベルを表示 | ライブの受信バッファを録画の長さのように表示しない。既存の標準再生・音量・全画面操作は維持 |

## シークバーの調査範囲

`SitePlayer.tsx` は mpegts.js 1.8.2 の `isLive:true` と video の標準 controls を使っている。インストール済み `src/core/mse-controller.js`、`src/player/seeking-handler.ts` と型定義を確認した。ライブ指定だけでブラウザーの時間軸が消えるわけではなく、生成 FLV の Chromium 再生でも有限の時間軸が表示されていた。今回の対応は CSS による表示調整であり、時刻補正や録画機能の追加ではない。ユーザーが見た異常の具体的な表示・ブラウザーまでは再現確認していない。

Firefox、OS 独自の全画面プレイヤーは同じ CSS に対応するとは限らない。バッファ内シーク自体は禁止していない。標準 controls を維持するために、独自プレイヤー UI への置き換えは行っていない。
