# 管理 UI の操作・表示改善

日付: 2026-09-14。対象は `ui/`。ユーザーの「操作上の問題をまず直し、その後見た目と使い勝手を直す」という依頼による。バックエンドの Go 実装・API 形式は変更していない。

## 修正内容と根拠

| 問題 | 根拠・修正 |
|:--|:--|
| info 編集で track が消える | 旧 `api.setChannelInfo` は省略した track を `{}` に補い、Go の `setChannelInfo` は track を全面置換していた。保存直前の `getChannelInfo` から track を取得して維持。取得失敗時は書き込まない |
| 選択チャンネルと詳細が食い違う | 旧詳細取得は選択変更時のクリア・要求中断・古い応答の排除がなかった。詳細を channelId ごとに再生成し、取得 effect の cleanup で中断と無効化を行う。切断対象 ID は表示中の詳細に固定 |
| キー取得失敗が無表示 | 配信ダイアログに読み込み・失敗・再試行・未発行時の案内を追加。取得できるまで開始ボタンを無効にする |
| 発行・停止などの重複操作 | 同期ロックと disabled 状態で二重送信を防止。操作失敗と完了を通知。対象を含む停止・切断・失効の確認を表示 |
| 読み込み失敗を「0 件」と誤認 | 初期ロード・空の正常結果・取得エラーを区別。再取得失敗時は前回データを残し、関連操作を無効にする |
| Bump の意味が不明 | リレーは「再接続」、配信は「YP 再通知」と表示。要求受理と接続成立、YP 未設定時の no-op を区別 |
| キーボード・狭い画面で操作しにくい | 選択をネイティブ button、フォームを関連付いた label、ダイアログを名前付き dialog に変更。閉じたら起動元へフォーカスを戻す。モバイルはフォーム 1 列、表内の横スクロールとチャンネル名列の固定 |
| キーが常時露出 | キーとキーを含む配信 URL を既定で伏せ字にし、表示・コピーを追加 |
| テンプレート CSS と管理画面 CSS が混在 | 色・余白・フォント・見出し・テーブル・ボタンを統一。ライト / ダーク、日本語ラベル、状態表示、集計と更新時刻を追加 |
| `StatusPage` の lint エラー | 取得・更新を共通の `useResource` に整理し、effect 内の同期 setState 呼び出しを除去 |

キー表示は肩越しの漏えい対策であり、認可を追加したわけではない。track の保持は取得と更新の 2 要求で行うため、その間の外部更新と原子的に整合する保証はない。現在の挙動は [UI 仕様](../spec/ui.md)、起動方法は [UI README](../../ui/README.md)。

## 検証

Playwright の全 API 応答をモック化し、実際の配信やキーには触れずに検証する。デスクトップ (1440px)、モバイル幅 (390px)、ダークテーマ (1280px) の Chromium で各 10 ケース、計 30 ケース。

- 編集時に最新の track を保持する
- track 取得失敗時は更新しない
- 遅延した旧チャンネルの応答を捨て、切断要求が表示対象の channelId / connectionId に一致する
- 配信時のキー取得失敗・再試行・送信無効化
- キー未発行時の説明と送信無効化
- キー発行の連続 submit が 1 要求になる
- 一覧エラーと空結果を区別し、手動更新で復旧する
- キーボードでの詳細選択、Escape、フォーカス復帰、再接続ラベルと対象
- ページ全体の横はみ出しがないこと、ダイアログの画面内配置、キー表示切替、ノード情報
- 保存中にダイアログを閉じられず、連続 submit が 1 要求になる

テストは `ui/tests/ui.spec.ts`。画面のスクリーンショットは `ui/test-results/` に出力する (Git 対象外)。デスクトップ・モバイル・ダークの画像を目視確認し、モバイルの表の過剰な折返しを修正した。

最終結果: `npm run lint`、`npm run build` は成功。上記環境での `npm test` は **30 / 30 成功**。`git diff --check` と追加・更新文書の相対リンク先も確認した。フォーカス復帰テストで当初 3 条件とも失敗した箇所は `Modal` の起動元フォーカス復元を追加して解消した。

この環境では Chromium の `libnspr4` / `libnss3` が不足し、sudo による依存導入は不可だった。Ubuntu パッケージを `/tmp/peercast-ui-browser.96pdOY/` に展開し、`LD_LIBRARY_PATH` と `FONTCONFIG_FILE` をテストプロセスだけに指定して実行した。日本語フォントも同ディレクトリに配置し、システムのパッケージは変更していない。通常環境の導入手順は UI README に記載した。

実 Go サーバーとの結合、実スマートフォン、Firefox / Safari は未検証。Go の変更はないため Go テストは再実行しない。
