# 本番サイトの管理パネル接続不具合

## 確認した問題

本番の一覧表示・Xログイン・視聴成功後、ユーザーから管理パネルが動かないとの報告を受けた。ローカルコードと本番用ビルド設定の確認結果を記録する。ブラウザーの実エラー・本番ログは未取得。

- `ui/src/api.ts` の管理JSON-RPC接続先はビルド変数未指定時に `http://127.0.0.1:7144/api/1`。本番Dockerfileはこの変数を設定していないため、管理画面は閲覧者のPCを接続先にする。
- `internal/site/server.go` の `Handler` は `/admin` のHTMLを配信するが管理APIは公開しない。CSPの `connect-src 'self'` も異なるオリジンへの接続を許可しない。
- 本番Caddyは `/mi` 配下をサイト専用8080へ転送する。管理JSON-RPCはノード7154側にあり、サイト側には認証付き接続経路がない。
- `internal/jsonrpc/server.go` の `Handler` は非loopback接続に管理Basic認証を要求し、loopback接続は例外扱い。単にサイトからloopbackへ無認証転送する修正では管理権限を外部公開してしまう。

## 修正

ユーザー指定に従いX数値IDの許可リストを採用した。[ADR 0024](../decisions/0024-site-admin-x-allowlist.md) に記録。

- `site.admin_x_ids` を追加。空設定は全員拒否し、開発ログインにも管理権限を付与しない。本番設定はユーザーが提示した管理者IDのみ登録。
- `/admin/api/1` はXセッション・許可ID・Origin・CSRFを毎回確認してから、固定のloopbackノードJSON-RPCに中継する。ブラウザーのCookie・Authorization・Origin・転送ヘッダーは渡さない。従来のノードAPI認証は変更しない。
- 本番管理UIの既定接続先を公開接頭辞込みの同一オリジンに修正し、認証・権限を確認してから管理コンソールを表示する。ログイン後は管理画面に戻れる。
- ローカルViteでは従来の接続先を維持し、明示的な `VITE_PEERCAST_ENDPOINT` も使える。空値は既定値として扱う。

## 検証

- `go vet ./...`・`go test ./...`: 成功。サンドボックスではTCP待受が拒否されたため外で実行。
- 新規Goテスト: 匿名・一般利用者・CSRF欠如・異なるOrigin・Origin欠如の拒否、許可IDの認証、開発ログイン・空許可リストでの拒否、不正ID、OAuth復帰先を確認。
- loopback上の実JSON-RPCサーバーへの中継でキー一覧取得とキー失効、ログアウト・期限切れ後の拒否を確認。上流URL固定とブラウザーヘッダー除去もテスト。
- `npm run lint`・ビルド: 成功。500kBを超えるJSチャンクへのサイズ警告あり。
- 既存Playwright63件・開発プロキシ1件: 成功。
- 本番 `/mi` ビルドのPlaywright2件: 成功。管理者・一般利用者・匿名のUI、同一オリジンの管理RPCとCSRF送信、既存視聴ページを確認。APIはモック。
- 本番UIテストの初回は手元の `.env.local` の管理API設定が混入して失敗した。テスト起動環境でこの値を空にし、本番の既定接続先を検証するよう修正して成功。
- 本番TOMLの管理者ID設定は構文・値を検証。差分チェック成功。
- `/mi` 用Dockerイメージのビルド成功。

本番へのコード更新・再ビルド・再起動、実Xログイン後の管理操作は未実施。VPSのアプリソースを更新してからAnsibleを適用する必要がある。メソッド仕様は変更していない。
